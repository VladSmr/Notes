# KP → IMDB Importer

Программа переносит ваши оценки фильмов с **Кинопоиска** на **IMDB**. Работает в два простых шага:

1. **Парсинг** — собирает ваши оценки с Кинопоиска и сохраняет их в файл.
2. **Проставление** — берёт собранные оценки и ставит их на IMDB.

---

## 🖥️ Для пользователей (установка и использование)

Эта часть предназначена для обычных пользователей — тех, кто просто хочет перенести свои оценки. Здесь нет технических деталей, только то, что нужно знать для работы.

### Что это за программа?

Программа переносит оценки фильмов с Кинопоиска на IMDB. Она делает это сама: вам нужно лишь один раз войти в свои аккаунты и нажать пару кнопок.

### Как установить

1. Перейдите на страницу **последнего релиза** и скачайте установщик **`.msi`**:
   👉 **[Скачать последнюю версию](https://github.com/VladSmr/Notes/releases/latest)**

   На странице релиза найдите asset вида **`KP IMDB Importer-<версия>.msi`** (например, `KP IMDB Importer-1.0.0.msi`) и скачайте его.
2. Запустите скачанный файл двойным щелчком мыши.
3. Подтвердите установку, если Windows попросит права администратора (нажмите «Да»).
4. Дождитесь окончания установки.

### Системные требования

- **Windows** (7/10/11 и новее).
- **Установленный Google Chrome** — программа управляет браузером для входа на Кинопоиск и IMDB.
- **Интернет-соединение.**

### Как запустить

После установки в меню «Пуск» (и на рабочем столе) появится ярлык **«KP IMDB Importer»**. Нажмите на него — откроется окно программы.

### Как пользоваться

Внутри программы следуйте шагам на экране:

1. Выберите **«Парсинг»** — программа откроет Кинопоиск. Войдите в свой аккаунт Кинопоиска и нажмите **Start Parsing**. Оценки будут собраны и сохранены.
2. Выберите **«Проставление»** — программа откроет IMDB. Войдите в свой аккаунт IMDB и нажмите **Start Proset**. Оценки будут проставлены.

Во время работы можно ставить процесс на паузу (**Pause**), продолжать (**Continue**) или полностью остановить (**Stop**).

### Где хранятся данные

Все файлы программы находятся в папке:

```
C:\Users\<ваше имя>\KP-IMDB-Importer
```

Здесь хранятся собранные оценки (`kp-ratings.csv`) и служебные файлы (логи, профиль браузера).

### Важные предупреждения

- ⚠️ **Не открывайте и не редактируйте файл `kp-ratings.csv` во время работы программы.** Программа постоянно записывает в него данные, и ручное изменение может привести к потере оценок.
- ⚠️ **Не запускайте «Парсинг» и «Проставление» одновременно.** Программа сама запретит второй запуск, пока первый не закончится — дождитесь завершения.
- ⚠️ Если файл `kp-ratings.csv` открыт в Excel, программа встанет на паузу — закройте файл и нажмите **Continue**.

В `pom.xml` по умолчанию `skipTests=true`, поэтому без аргументов тесты **пропускаются**. Запускайте явно:

```bash

mvnw test -DskipTests=false -Dgroups=integration
```

### Сборка десктоп-установщика `.msi`

Десктоп-версия — это JavaFX WebView-оболочка, которая рендерит тот же Thymeleaf-UI в настоящем окне. Сборка в установщик выполняется через `jpackage` (входит в JDK 21).

#### Требования к машине сборки

- **JDK 21** (включает `jpackage` и `jlink`).
- **JavaFX 21.0.2** (win-модули в локальном Maven-кэше — уже объявлены в `pom.xml`).
- **WiX Toolset 3.x** — нужен только для `--type msi` (одноразовая установка, скачать с https://wixtoolset.org/docs/v3/). Без WiX можно собрать только промежуточный `app-image`, `.msi` не создастся.

#### Команды

```bash
# 1. Fat-JAR (для разработки)
mvnw clean package -DskipTests=false

# 2. app-image (промежуточная папка target/dist/KP IMDB Importer/)
mvnw package -Pdesktop -DskipTests=false

# 3. .msi (нужен WiX) — результат: target/dist/KP IMDB Importer-1.0.0.msi
mvnw package -Pdesktop-msi -DskipTests=false
```

Либо напрямую скриптом (из корня проекта):

```bash
powershell -ExecutionPolicy Bypass -File build-msi.ps1 -Msi
```

> Оба desktop-профиля (`desktop`, `desktop-msi`) делегируют фактическую сборку в `build-msi.ps1`: тонкий jar + `app/*`, jlink runtime-image с JavaFX, jpackage. Скрипт вызывается с `-SkipBuild`, т.к. Maven уже собрал thin jar к фазе `package`.

#### Непрерывная интеграция (GitHub Actions)

Workflow `.github/workflows/build-msi.yml` на каждый push в `main` (и по ручному запуску `workflow_dispatch`):

1. Ставит **JDK 21 (Temurin)** через `actions/setup-java` (с кешем Maven-репозитория).
2. Запускает юнит-тесты (`mvnw clean test -DskipTests=false`).
3. Ставит **WiX Toolset 3.x** (`choco install wixtoolset`) — jpackage находит его автоматически в `C:\Program Files (x86)\WiX Toolset v3.14\bin`.
4. Собирает `.msi` через `build-msi.ps1 -Msi` (JavaFX win-jar подтягиваются в локальный m2-кеш самой сборкой).
5. Загружает `.msi` как **build-artifact** (сохраняется всегда).
6. **Публикует GitHub Release (вариант B)** — только если версия в `pom.xml` изменилась относительно последнего опубликованного Release. Если версия не менялась — Release не трогается.

Версия для релиза берётся из `pom.xml` (`<version>`), тег релиза = версия, asset = `KP IMDB Importer-<версия>.msi`.

После установки `.msi` в меню «Пуск» и на рабочем столе появляется ярлык **«KP IMDB Importer»**. По клику открывается десктоп-окно, которое само запускает встроенный сервер и Chrome для Selenium. Пользователю не нужна установленная Java — jpackage включает вырезанный JRE 21.

> Иконка приложения подключена: `packaging/app.ico` (валидный многомерный `.ico`, перегенерируется скриптом `packaging/create-icon.ps1`, если исходный файл — PNG). `build-msi.ps1` автоматически передаёт `--icon packaging/app.ico` в jpackage.

### Рабочая папка приложения

В установленной версии (десктоп-окно / `.msi`) программа ставится в Program Files, куда писать нельзя. Поэтому все рабочие файлы по умолчанию хранятся в рабочей папке приложения:

```
%USERPROFILE%\KP-IMDB-Importer        (например C:\Users\<user>\KP-IMDB-Importer)
├── kp-ratings.csv                    # дамп оценок КП (результат парсинга)

```

Пользователь по-прежнему может указать собственную директорию на формах — рабочая папка подставляется только как значение по умолчанию.

## 🔄 Как это работает

Перенос оценок выполняется двумя независимыми этапами:

1. **«Парсинг»** — получение оценок пользователя с Кинопоиска и сохранение их в дамп `kp-ratings.csv`.
2. **«Проставление»** — чтение дампа и проставление оценок на IMDB.

Этапы запускаются отдельно друг от друга и могут выполняться в разное время: сначала парсинг формирует дамп, затем проставление работает уже только с ним. **Одновременный запуск парсинга и проставления запрещён** — приложение отклоняет второй запуск, пока первый не завершён.

### Этап «Парсинг» (КП → дамп)

Оценки пользователя получаются одним из **двух** способов (выбор на странице приложения):

| Способ | Ключ | Что делает | Что нужно |
|--------|------|------------|-----------|
| **API (token)** | `api` | Быстрый парсинг через kinopoiskapiunofficial.tech без браузера. API отдаёт **все** оценки пользователя | ID пользователя КП, API-токен |
| **Browser (Selenium)** | `selenium` | Полный парсинг всех оценок в открытом Chrome (залогиненная сессия), догружает оригинальные названия | ID пользователя КП, вход в КП в Chrome |

> Способ «Сохранённый дамп» из парсинга убран: повторный прогон уже обработанных фильмов теперь выполняет отдельный этап «Проставление» (см. ниже).

Результат парсинга сохраняется в `kp-ratings.csv` (перезаписывается после каждых 5 обработанных фильмов, чтобы статусы появлялись даже при остановке приложения).

### Этап «Проставление» (дамп → IMDB)

- Источник данных — `kp-ratings.csv` из директории логов (путь указывается на форме).
- Для каждого фильма выполняется поиск на IMDB (по imdbId из дампа или по названию и году на странице поиска):
  - если оценка уже стоит та же — пропуск (**пропущено (уже стоит оценка)**);
  - если оценка отличается — пропуск (**руками (оценки отличаются)**);
  - если фильм не нашёлся — **не найден**;
  - иначе проставляется оценка с КП (**успешно**), после чего результат проверяется повторным чтением оценки.
- Уже обработанные в прошлых запусках фильмы (статусы в дампе) пропускаются автоматически.
- Между фильмами пауза 1–2 секунды (имитация пользователя).

### Использование

#### Шаг 0 — выбор этапа

Открыть `http://localhost:8085/notes/` — страница-«выбор» с двумя карточками: **«Парсинг»** и **«Проставление»**.

#### Парсинг

1. На странице выбора нажать **«Парсинг»** → открывается выбор способа (две карточки: API / Browser) с пояснением. Выбрать и нажать «Next».
2. Форма показывает только нужные поля:
   - Browser — ID пользователя КП и директорию логов;
   - API — дополнительно API-токен.
3. Если `kp-ratings.csv` в указанной директории уже существует — появится предупреждение о перезаписи дампа (подтвердить или вернуться).
4. Нажать «Next» — откроется Chrome (для Selenium). На странице показывается число оценок на КП (для Selenium — реальное число, для API — сколько вернул API).
5. **Вручную** войти в аккаунт Кинопоиска в открывшемся окне (новая вкладка).
6. Нажать **Start Parsing** — парсинг пойдёт в фоне, страница с прогрессом обновится автоматически.
7. После завершения — страница со статистикой и таблицей по каждому фильму (`/parsing-result`).

#### Проставление

1. На странице выбора нажать **«Проставление»** → форма, где указывается путь к директории с дампом `kp-ratings.csv`.
2. Нажать «Next» — откроется Chrome на imdb.com.
3. **Вручную** войти в аккаунт IMDB в открывшемся окне (новая вкладка).
4. Нажать **Start Proset** — проставление пойдёт в фоне, страница с прогрессом обновится автоматически.
5. После завершения — страница со статистикой и таблицей по каждому фильму (`/result`).

#### Во время любого этапа

- Доступны кнопки **Pause** (пауза после текущего фильма), **Continue** (продолжить), **Stop** (полная остановка после текущего фильма; дамп сохраняется).
- Если `kp-ratings.csv` открыт в Excel, этап встаёт на паузу с подсказкой закрыть файл и нажать Continue.
- Прогресс и лог видны в реальном времени (SSE) на раздельных страницах прогресса парсинга и проставления.

> **Важно:** не трогайте `kp-ratings.csv` во время процесса — файл перезаписывается по ходу работы, и ручное редактирование может привести к потере данных или конфликту записи.

## 📁 Файлы в директории логов

| Файл | Описание |
|------|----------|
| `kp-ratings.csv` | Дамп оценок КП со статусами. UTF-8 с BOM, разделитель `;`, заголовок `title;original_title;english_title;year;rating;kp_id;imdb_id;status;error`. Запись атомарная (сначала `.tmp`, затем rename) — при сбое файл не усекается. |

Подробный лог хода процесса пишется в консоль приложения (SLF4J).

### Статусы (колонка `status` в CSV)

| Статус | Описание |
|--------|----------|
| успешно | Оценка проставлена на IMDB |
| не найден | Фильм не найден на IMDB |
| пропущено (уже стоит оценка) | На IMDB уже стоит такая же оценка |
| руками (оценки отличаются) | На IMDB стоит другая оценка |
| ошибка | Произошла ошибка при обработке |

Статусы записываются в дамп по ходу проставления — при повторном запуске уже обработанные фильмы пропускаются.

### Основные маршруты

| URL | Метод | Назначение |
|-----|-------|------------|
| `/` | GET | Страница-«выбор» этапа (Парсинг / Проставление) |
| `/main` | GET | Выбор способа парсинга |
| `/method` | POST | Форма данных для выбранного способа парсинга |
| `/submit` | POST | Подготовка парсинга (с проверкой перезаписи дампа) |
| `/submit-confirmed` | POST | Подтверждение перезаписи дампа → открытие браузера КП |
| `/start-parsing` | POST | Запуск этапа «Парсинг» |
| `/parsing-result` | GET | Результат этапа «Парсинг» |
| `/proset` | GET | Форма проставления (путь к дампу) |
| `/proset-submit` | POST | Подготовка проставления (проверка дампа, открытие IMDB) |
| `/start-proset` | POST | Запуск этапа «Проставление» |
| `/result` | GET | Результат этапа «Проставление» |
| `/progress`, `/log` | GET | SSE: прогресс и лог текущего этапа |
| `/stop`, `/pause`, `/resume` | POST | Управление текущим этапом |
| `/error` | GET | Страница ошибки |
